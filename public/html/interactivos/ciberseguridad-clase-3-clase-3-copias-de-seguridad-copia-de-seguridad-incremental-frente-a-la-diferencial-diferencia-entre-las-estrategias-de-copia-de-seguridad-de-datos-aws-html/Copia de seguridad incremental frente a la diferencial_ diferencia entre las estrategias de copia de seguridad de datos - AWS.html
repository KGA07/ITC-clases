¿Cuál es la diferencia entre las copias de seguridad incrementales, diferenciales y otras?

Las copias de seguridad incrementales y diferenciales son dos estrategias para realizar copias periódicas y frecuentes de los datos con fines de recuperación ante desastres. Los sistemas de TI de cualquier compañía pueden sufrir una interrupción de manera inesperada debido a circunstancias imprevistas, como cortes de energía, fenómenos naturales o errores de seguridad. Es fundamental realizar copias de seguridad de los datos para no perder información crítica para las operaciones. Sin embargo, es posible que debido al volumen de datos no resulte práctico realizar una copia de seguridad completa en cada instante. Una estrategia de copia de seguridad diferencial solo copia los cambios en los datos desde la última copia de seguridad completa. Por otra parte, una estrategia de copia de seguridad incremental copia los datos modificados desde la última copia de seguridad.

Copia de seguridad completa, copia de seguridad incremental y copia de seguridad diferencial: cómo funcionan

Hay tres estrategias principales de copia de seguridad de datos, que detallamos a continuación.

Copia de seguridad completa

Cuando el software de copia de seguridad realiza una copia de seguridad completa, copia todo el conjunto de datos, independientemente de si se han realizado cambios en dichos datos. Por lo general, este tipo de copia de seguridad se realiza con menos frecuencia por motivos prácticos. Por ejemplo, puede llevar mucho tiempo y también ocupar una gran cantidad de espacio de almacenamiento. Las alternativas a las copias de seguridad completas de datos incluyen las copias de seguridad diferenciales o incrementales.

Copia de seguridad incremental

Una copia de seguridad incremental solo copia los datos modificados desde la última copia de seguridad. Por ejemplo, si realizó una copia de seguridad completa el domingo, la copia de seguridad incremental del lunes solo copiará los cambios realizados desde la copia de seguridad del domingo. El martes, solo copiaría los cambios del archivo de imagen de copia de seguridad desde la copia de seguridad del lunes.

Respaldo diferencial

Una estrategia de copia de seguridad diferencial copia solo los datos recién agregados y modificados desde la última copia de seguridad completa. Si la última copia de seguridad completa se realizó el domingo, una copia de seguridad del lunes copiará todos los cambios realizados desde el domingo. Si hubieras realizado otra copia de seguridad el martes, también copiaría todos los cambios realizados desde el domingo. El tamaño del archivo de copia de seguridad aumentaría progresivamente hasta la próxima copia de seguridad completa.

Diferencias clave: copia de seguridad incremental frente a copia de seguridad diferencial

Las estrategias de copia de seguridad incremental y diferencial ofrecen diferentes ventajas en función del rendimiento de copia de seguridad que desee lograr. A continuación, presentamos los factores diferenciadores clave.

Velocidad de copia de seguridad

Las copias de seguridad diferenciales requieren más tiempo para completarse que las copias de seguridad incrementales, ya que el tamaño del archivo de imagen de copia de seguridad aumenta a diario.

Por el contrario, el proceso de copia de seguridad incremental suele ser más rápido y eficiente debido a que los archivos de copia de seguridad son consistentemente pequeños.

Utilización del espacio de almacenamiento

Las copias de seguridad incrementales requieren menos espacio de almacenamiento.

Las copias de seguridad diferenciales ocupan más espacio de almacenamiento a medida que aumenta el tiempo transcurrido desde la última copia de seguridad completa. Una estrategia de copia de seguridad diferencial tiene como objetivo reducir el tiempo de restauración mediante la compensación del espacio de almacenamiento.

Costo de implementación

Por lo general, una copia de seguridad incremental ahorra espacio de almacenamiento de copia de seguridad y ancho de banda de la red. A largo plazo, una copia de seguridad completa combinada con copias de seguridad incrementales frecuentes es la opción más rentable.

Por el contrario, las copias de seguridad diferenciales se vuelven más costosas con el tiempo y es necesario realizar copias de seguridad completas con más frecuencia para aumentar la eficiencia.

Velocidad de restauración de datos

Si bien las copias de seguridad incrementales son rentables, restaurar los datos puede llevar mucho tiempo y resultar complejo. Este proceso requiere contar con la primera copia de seguridad completa y todas las copias de seguridad incrementales posteriores para restaurar los datos. Por ejemplo, si se produce un fallo el miércoles, tendría que revisar todas las copias de seguridad del domingo al martes, identificar los cambios y restaurarlos de forma acumulativa. El proceso se hace más complejo a medida que aumenta el tiempo transcurrido desde la última copia de seguridad completa.

Por otro lado, la restauración a partir de copias de seguridad diferenciales solo requiere la primera copia de seguridad completa y la última copia de seguridad diferencial. Además, es un proceso mucho más rápido.

Cuándo utilizar la copia de seguridad diferencial y cuándo la incremental

Al decidir si va a utilizar una copia de seguridad diferencial o incremental, puede tener en cuenta varios factores en función de sus requisitos y presupuesto.

Frecuencia de cambios de datos

Las copias de seguridad incrementales son más adecuadas si su organización gestiona una cantidad importante de datos que sufren cambios con frecuencia. Puede ahorrarle tiempo y costos de copia de seguridad.

Por otro lado, si opta por copias de seguridad diferenciales, los costos podrían aumentar rápidamente.

Requisitos empresariales

A la hora de decidir el mejor tipo de copia de seguridad que implementar en su organización, debe tener en cuenta los recursos disponibles y la política de copia de seguridad y recuperación de datos de su empresa.

Por ejemplo, los datos de los productos son fundamentales para una aplicación de comercio electrónico, y puede utilizar copias de seguridad diferenciales para reducir los tiempos de restauración y reducir al mínimo el tiempo de inactividad.

Sin embargo, puede optar por archivar archivos de imagen o datos de video con una sola copia de seguridad de datos completa si no cambia con el tiempo.

Copia de seguridad sintética y copia de seguridad incremental para siempre

Existen otras estrategias de datos de copia de seguridad además de las copias de seguridad incrementales y diferenciales. 

Copia de seguridad completa sintética

Una copia de seguridad completa sintética compara los datos que han cambiado en el origen con la copia de seguridad completa original y todas las copias de seguridad incrementales para crear la siguiente copia de seguridad completamente sintetizada. En lugar de almacenar solo el archivo de copia de seguridad incremental, el servidor de copia de seguridad consolida los cambios con la última copia de seguridad completa y crea una copia de seguridad completa sintética. El proceso es invisible para los usuarios finales.

En una copia de seguridad completa sintética, no se ahorra espacio de almacenamiento, pero sí ancho de banda de la red. Solo envía cambios incrementales al servidor en lugar de enviar todos los datos. El servidor utiliza los datos que ya tiene para crear la copia de seguridad completa.

Copia de seguridad incremental para siempre

Todas las demás estrategias de copia de seguridad que se describen en esta guía incluyen realizar copias de seguridad completas periódicas. Sin embargo, si implementa una copia de seguridad incremental para siempre, solo realizará una copia de seguridad inicial completa. Posteriormente, realiza una secuencia de copias de seguridad incrementales (para siempre) de forma indefinida. 

El servidor de copia de seguridad almacena todos los conjuntos de copia de seguridad en una biblioteca de cintas o en una matriz de discos grande. Automatiza el proceso de restauración para que imite la restauración a partir de una copia de seguridad completa.

¿Cómo puede AWS cumplir con sus requisitos de copia de seguridad de datos?

Amazon Web Services (AWS) ofrece varias opciones para respaldar su estrategia de copia de seguridad. Si siente curiosidad, puede obtener más información acerca de los servicios de copia de seguridad y restauración de AWS. A continuación, se indican varios ejemplos:

  • AWS Backup ofrece un servicio rentable, completamente administrado y basado en políticas que simplifica la protección de datos a escala.
  • AWS Storage Gateway proporciona aplicaciones locales con acceso a un almacenamiento en la nube prácticamente ilimitado
  • Amazon Simple Storage Service (Amazon S3) es un servicio de almacenamiento de objetos que ofrece escalabilidad, disponibilidad de datos, seguridad y rendimiento líderes en el sector.

Puede utilizar estos servicios para configurar sus políticas de copia de seguridad preferidas en la nube o ir más allá de las copias de seguridad. Si siente curiosidad, puede obtener más información acerca de la recuperación ante desastres y el archivado.

What is Block Storage?

Block storage is technology that controls data storage and storage devices. It takes any data, like a file or database entry, and divides it into blocks of equal sizes. The block storage system then stores the data block on underlying physical storage in a manner that is optimized for fast access and retrieval. Developers prefer block storage for applications that require efficient, fast, and reliable data access. Think of block storage as a more direct pipeline to the data as opposed to file storage which has an extra layer consisting of a file system (NFS, SMB) to process before accessing the data.

A relational database is a collection of data items with pre-defined relationships between them. These items are organized as a set of tables with columns and rows. Tables are used to hold information about the objects to be represented in the database. Each column in a table holds a certain kind of data and a field stores the actual value of an attribute. The rows in the table represent a collection of related values of one object or entity. Each row in a table could be marked with a unique identifier called a primary key, and rows among multiple tables can be made related using foreign keys.
